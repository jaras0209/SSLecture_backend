# SSLecture Backend

SSLecture 前端（`../SSLecture`）的後端 API。規格以前端專案的文件為準：

- `docs/backend_api_spec.md`：API 規格
- `docs/database_schema.md`：資料庫設計
- `docs/oauth2_social_login_spec.md`：Google / LINE 社群登入

## 技術組合

| 項目 | 版本 / 套件 |
|------|-------------|
| Java | 25 |
| Spring Boot | 4.2.0-RC2（4.2.0 正式版發布後更新 `pom.xml` 的 parent 版本） |
| Web / 驗證 | `spring-boot-starter-webmvc`、`spring-boot-starter-validation` |

| 其他 | Redis、Mail（規劃中）、Actuator、springdoc-openapi、Lombok、MapStruct |

| 格式 | google-java-format 2.0.0（透過 Spotless） |

## 本地開發

需要 JDK 25（`JAVA_HOME` 指向它）。不需要另外安裝資料庫：

```bash
./mvnw spring-boot:run
```

- 預設 profile 為 `dev`，使用 H2 檔案資料庫（`./data/`），Liquibase 會自動建表並灌入種子資料
- 開發用帳號：`student`、`teacher`、`pastor`、`parent`、`admin`，密碼都是 `123456`（只存在 dev / test）
- Swagger UI：http://localhost:8080/swagger-ui.html
- H2 主控台：http://localhost:8080/h2-console（JDBC URL 見 `application-dev.yml`，帳號 `sa`、無密碼）
- 健康檢查：http://localhost:8080/actuator/health
- 想清空資料重來：停掉程式後刪除 `./data/`

前端的 `.env.development` 已設定 `VITE_API_BASE_URL=http://localhost:8080`，CORS 預設允許 `http://localhost:5173`。

## 資料庫管理（Liquibase）

changelog 位於 `src/main/resources/db/changelog/`：

```
db.changelog-master.yaml        主檔：依序 include、定義 H2 / PostgreSQL 的語法差異
changes/001-initial-schema.sql  22 張表（對應 database_schema.md 第 6 節）
changes/002-regex-constraints.sql  帳號格式 CHECK（兩種資料庫各一份）
changes/003-seed-reference-data.sql  教會、課程、專題大綱（所有環境）
changes/004-seed-dev-users.sql  開發用帳號（只在 dev、test）
```

規則：

1. **已提交的 changeset 不可修改**，要改結構就新增 `NNN-描述.sql` 並加到主檔
2. SQL 必須同時能在 H2 與 PostgreSQL 執行；語法不同時用主檔的 property（如 `${uuid_fn}`），或在 changeset 加 `dbms:h2` / `dbms:postgresql`
3. 只給開發用的資料加 `context:dev,test`；正式環境只跑 `prod` 與未標 context 的 changeset

### 為何開發用 H2、正式用 PostgreSQL

評估後採用「H2 開發 + PostgreSQL 正式」，前提是 changelog 寫成兩邊都能跑。與 `database_schema.md` 原始 SQL 的調整：

| 原始寫法（PostgreSQL 專用） | 調整後 | 說明 |
|---|---|---|
| `CREATE TYPE ... AS ENUM` | `VARCHAR` + `CHECK (... IN (...))` | JPA 的 `@Enumerated(STRING)` 也比 PG enum 好對應 |
| `gen_random_uuid()` | `${uuid_fn}` | H2 為 `RANDOM_UUID()` |
| `lower(email)` 部分唯一索引 | 小寫 CHECK + 一般 `UNIQUE` | 規格本來就要求信箱小寫儲存 |
| `~` 正規表示式 CHECK | 兩種資料庫各一個 changeset | H2 用 `REGEXP_LIKE` |
| `INET` | `VARCHAR(45)` | |
| `TEXT[]` | `${text_array}` | H2 為 `CHARACTER VARYING ARRAY` |
| `BIGSERIAL`、`NOW()`、`btrim()` | `GENERATED BY DEFAULT AS IDENTITY`、`CURRENT_TIMESTAMP`、`TRIM()` | 標準 SQL |
| `AT TIME ZONE 'Asia/Taipei'` | 程式中轉換（`WallClockTime`） | 不依賴資料庫函式 |

H2 的限制：它只是「相容模式」，不會發現 PostgreSQL 特有的問題（例如保留字不同、鎖定行為、`TEXT[]` 運算子）。
所以 `PostgresSchemaTests` 會在**有 Docker 時**以 Testcontainers 在真正的 PostgreSQL 上跑一次 Liquibase；
沒有 Docker 時自動略過。上線前或 CI 至少要在有 Docker 的環境跑過一次。
若之後要用 PostgreSQL 特有功能（JSONB、全文檢索等），建議改為本地也用 PostgreSQL。

## 程式碼格式

使用 [google-java-format](https://github.com/google/google-java-format) 2.0.0：

```bash
./mvnw spotless:apply   # 自動排版
./mvnw spotless:check   # 只檢查（mvn verify 時會自動執行，格式不符則建置失敗）
```

IntelliJ 可安裝 google-java-format 外掛，存檔時就排好。

## Commit 規範

遵守 [Conventional Commits](https://www.conventionalcommits.org/zh-hant/v1.0.0/)：

```
<type>(<scope>): <描述>

feat(auth): 新增帳號密碼登入 API
fix(booking): 修正已取消場次仍可確認的問題
feat(api)!: 調整回應格式        ← ! 表示破壞性變更
```

`type`：`feat` `fix` `docs` `style` `refactor` `perf` `test` `build` `ci` `chore` `revert`

clone 後執行一次，讓 git 在 commit 時自動檢查格式：

```bash
git config core.hooksPath .githooks
```
